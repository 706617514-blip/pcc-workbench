### 关于「发券 420 张、核销 84 张、核销率 20%」

这是你们汇报里的数字。产品内同一口径下显示的是 **发放 231 / 领取 140 / 核销 35**（默认 10/01–10/29 窗口）——两套数不是矛盾，而是**抽样不同**：数据由固定种子生成，本机重生成时随机抽取与当时那台机器略有差异（约 0.6%）。

汇报时只有两种做法是诚实的：**要么把汇报里的数字改成产品实测值**，要么说明「汇报数据来自另一版数据快照」。不要两处同时出现不同的数。

## 三、美化建议（需你确认做哪些）

1. **圆角/间距统一**：目前卡片混用 12/14/16px，卡片间距 16/20px 混用 → 统一成一套（12px 圆角 / 20px 间距）
2. **表格**：加斑马纹 + 悬停高亮，表头吸顶
3. **指标卡**：数字旁加环比小箭头（↑12%），比纯数字更有"看板感"
4. **空态插图**：一个淡淡的 PCC 杯型线稿，比一行灰字好
5. **页面切换淡入**：现在切页是硬切，加 120ms 淡入
6. **窄屏适配**：演示用 16:9 投影时不需要，优先级最低

> 我的判断：**1、2、5 值得做**（改动小、观感提升明显）；3 需要更多数据口径，4 需要画图，收益一般。

## 四、PRD 3.1 与产品的两处不一致（要你定，外审会看出来）

### 1. 门店本地券：产品有，PRD 没有

- 产品：6 种券，含**门店本地券 8.5 折**（1,061 张券实例，门店账号创建本店活动时使用）
- PRD 3.1 表 6：只有 **5 种券**（新人、生日、30 天回流、万圣限定、学生），全文 0 次提到「门店本地券」
- 但 PRD 又要求「门店员工可创建仅适用于本门店的活动」——**那门店活动用哪种券？PRD 没定义**

两种收口方式：

- **A（改 PRD）**：在表 6 补一行「门店本地券 8.5 折，门店活动专用，领取日起 14 天，每人一次」
- **B（改产品）**：门店活动复用「万圣限定券」式的主题券，删除门店本地券类型

我倾向 **A**：门店活动是 PRD 明确要有的能力，缺券种定义是 PRD 的疏漏，不是产品的错。

### 2. 频次上限数值来源

- PRD 3.1 §6.2.1：「待 PCC 确认：全局营销消息频次上限…这些**不得用示意数值直接作为真实运营政策**」
- 产品：每日 1 张、近 7 天 3 张（写死在 `engine.js` 的 `frequency_cap`，可配置）

汇报时必须明确说「这是工作台的**可配置项**，不是 PCC 现行政策」。说成"我们的规则"会被外审追问。

# PCC 会员营销工作台 —— 优惠券自动发放助手

> COMM7085 Final Project · Group F
> 依据 `PCC_PRD_最终.docx`（产品需求文档）实现的完整可交互网页产品。

这是一个**可直接在浏览器中运行**的营销自动化（MA）工作台原型，实现了 PRD 定义的全部
后台页面、券规则、审批流程、发券引擎、数据看板、AI 活动助手与消费端静态原型。
所有数据均为**合成数据**，不含任何真实 Pacific Coffee 会员资料。

## 一、快速开始

数据通过 `fetch` 读取，需经 HTTP 服务访问（不能用 `file://` 直接打开）：

```bash
cd pcc-workbench
python3 -m http.server 8777
# 浏览器打开 http://127.0.0.1:8777/app/index.html
```

首次加载会读取约 16 MB 合成数据，请稍候数秒。

## 三、已实现的 PRD 需求对照

### 5.1 信息架构与关键页面
左侧导航：总览／活动创建／活动管理／审批中心／发送记录／设置（＋消费端原型）。
AI 助手为右下角悬浮按钮，点击后从右侧打开抽屉，不新增左侧导航项；模态窗口打开时隐藏入口。

- **总览**：发放／主动领取／核销／昨日回流券领取（门店端为核销数／关联订单实付／本店适用活动／核销异常）
- **券种／活动筛选**：收纳为一个多选字段，鼠标移入或点击展开，「全部」与其他选项互斥
  - **批量勾选**：勾选期间下拉保持展开，可一次性选完所有选项；底部操作条显示「已修改，点击应用生效」，点「应用」（或点面板外部／按 Esc）后一次性生效并刷新页面，避免每点一项就重算、跳转。
- **日期范围**：点击展开月历，两次点击选起止日，支持跨月；点击年月栏可切换月份与年份
- **导出数据**：弹窗展示已应用筛选范围，可选汇总指标／各活动表现／每日趋势，导出 XLSX 或 CSV；
  仅导出当前账号有权查看的汇总数据，不含会员个人明细，操作留审计
- **活动创建**：同页筛选会员并预览人数；创建入口只在此页
  - **门店范围**：总部账号可**多选门店**（不选任何门店＝全港门店），筛选与预览只统计所选门店的交易，
    并展示「覆盖门店」列标明每位会员命中哪几家所选门店；门店账号的范围由权限**锁定为本店**，
    前端只读、服务端对越权参数强制拒绝（PRD 2.1 / 9.1）
  - **活动适用范围**：总部可将活动限定为全港、指定单店、或筛选所选的多个门店；
    门店活动固定为本店且须经总部审批
  - **累计消费／购买杯数**：**自由区间**，可只填最低、只填最高、或两者都填，任意数值均可
    （PRD 表 12 只要求「按杯数、消费金额筛选」，未限定档位）；下方提供常用区间快捷 chip，
    点击即可填入但仍可自由修改。非数字字符自动过滤，填反了会自动交换上下限
- **活动管理**：全部活动／自动规则／限定主题／门店活动四个分类
- **审批中心**：待办与历史同页，可按状态与审批日期筛选；已批准／已驳回只读，不再显示批准按钮
- **发送记录**：按发放方式、活动、结果、日期筛选；失败记录可查看原因代码与重试历史
- **设置**：界面语言（简中／繁中／English，按账号保存）＋门店账号与权限管理

### 6.2.1 示例券规则（表 6 全量实现）

| 券种 | 折扣 | 触发 | 有效期 | 每人次数 | 积分同用 |
|---|---|---|---|---|---|
| 新人券 | 7 折 | 注册当日 | 注册当日起 7 天 | 每位会员一次 | 不可同用 |
| 生日券 | 5 折 | 生日当天 | 生日当日起 7 天 | 每年一次 | 不可同用 |
| 30 天回流券 | 8 折 | 连续 30 天未消费 | **未领取长期保留；领取日起 3 天** | 同一轮不重发 | 可同用 |
| 万圣限定券 | 8 折 | 主题窗口 | 节前一周约半个月 | 每人一次 | 可同用 |
| 学生优惠券 | 7.5 折 | 学生资格有效 | 领取日起 7 天 | 每月一次 | 可同用 |
| 门店本地券 | 8.5 折 | 门店活动 | 领取日起 14 天 | 每人一次 | 可同用 |

结算规则：每笔订单最多使用一张券；可叠加券允许「先积分抵付、再对剩余金额应用折扣」
（积分按每 20 分抵 HK$1）；不可叠加券不能与积分同单使用。

### 6.2 状态机（表 7）
- 活动／规则：草稿 → 待审批 → 已批准／已驳回 → 运行中／停用
- 发券任务：待执行 → 成功／失败 → 待重试／已处理
- 模拟通知：待发送 → 已发送／失败（**「成功」指已创建券实例，不等于会员领取或核销**）
- 券实例：待领取 → 已领取 → 已使用／已过期／已作废

### 6.1 服务端强制能力
- 资格检查：范围／同意／频控／同轮去重，**fail-closed**
- 幂等发券键：`活动 + 会员 + 触发轮次`，重跑任务不重复建券；重试沿用原键
- 门店数据隔离：门店账号查询一律强制其所属 `store_id`，跨店会员不可见，电话服务端掩码
- 频控：每日 1 张、近 7 天 3 张（PRD 标为待 PCC 确认，此处为工作台可配置项）

### 6.3 AI 组件（表 8 / 表 9 / 表 10）
| 组件 | 实现 |
|---|---|
| A 自然语言活动配置 | 一句话 → 结构化活动草稿 + 理解说明 |
| B 门店本地化改写 | 按门店商圈类型／季节／语言给出门店版建议与理由 |
| C 权限守门（确定性，fail-closed） | 门店范围／折扣上限／券种授权／审批要求／有效期五项检查 |
| E 审批分流 | 按当前启用角色路由（香港路由至总部，区域层级预留不启用） |
| F 拦截解释 | 引用任务编号、原因代码与原始时间，不提供直接重试或发送按钮 |

抽屉状态：初始引导／生成中（禁止重复提交）／结果／规则拦截／服务失败（保留输入可重试）／无权限。
AI 只生成「建议／草稿」，人员点击「填入活动表单」后仍可修改并亲自提交审批。

### 5.5 消费端静态原型
三屏：首页（已登录，含待领取提示与最新消息轮播）、我的奖赏（待领取／可使用／已使用）、
优惠券详情。可实际点击「領取優惠券」完成领取，回流券在领取前**不计 3 天有效期**，
领取后有效期开始计算，结果实时进入后台看板。

## 四、合成数据说明（PRD 3.2）

- **规模**：5,000 名会员、303,678 笔交易（覆盖 12 个月），满足 PRD「≥5,000 会员 / ≥50,000 交易」
- **固定种子**：`SEED = 7085`，输出 `data/assumptions.json` 假设清单，可完整复现
- **非均匀分布**：6 种会员原型驱动（频次／客单／时段／偏好商品／流失风险相互一致）；
  交易时段叠加早高峰(8-10)、午市(13)、下午茶(15-18) 三峰；周末整体后移；
  季节因子按香港气候假设；公众假期客流上浮
- **缺失值处理**：部分会员生日月日缺失（不触发生日券）、注册日期缺失（不触发新人券）、
  学生资格过期（不发学生券）、同意记录缺失（跳过通知）
- **声明**：以上均为**测试假设**，不代表 PCC 真实客流规律；接入授权样本前须重新校准。
  合成数据只能验证系统与统计方法，不能证明真实营销提升。

## 八、两人协作（Git）

仓库放在 GitHub 私有仓库，两人各自在本地改、用 Git 同步。

### 第一次（每台机器只做一次）

```bash
git clone <仓库地址> pcc-workbench
cd pcc-workbench
# Windows：双击「启动网页.cmd」
# macOS / Linux：python3 -m http.server 8777
```

### 日常流程

```bash
git pull                      # 开工前先拉，别在旧代码上改
# …… 改代码 ……
# 双击「启动网页.cmd」在浏览器里看效果
# 控制台跑 await PCC_ACCEPTANCE.run()，确认 16/16
git add -A
git commit -m "说明这次改了什么"
git push
```

### 避免互相覆盖的三条约定

1. **改前必 pull，改完必 push**；同一时段尽量不碰同一个文件（例如一人改 `app.js`，一人改 `engine.js`）。
2. **`app/data/*.json` 是 15MB 生成数据**，除非确实要重新生成，否则不要动它、也不要提交改动
   （`.gitattributes` 已把它标记为二进制，避免 diff 变成几十万行）。
3. **提交前跑一遍验收**，别把 16/16 改成 15/16；`app/selftest.html` 打开即可看到结果。

### 发生冲突时

```bash
git pull
# 冲突文件里会出现 <<<<<<< / ======= / >>>>>>> 标记，手工保留正确的一版
git add <冲突文件>
git commit
```

实在解不开：`git checkout --theirs <文件>` 取对方版本，或 `--ours` 取自己版本，再手动补。
